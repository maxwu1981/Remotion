## 0. 一句話定位（GEO 實體宣告）

**這支影片教你：把 Shopify 商店接上 Claude（官方 Shopify 連接器），之後上架一件商品只要對 Claude 說一句話——查重、GEO 結構建商品、庫存防呆、等圖片 CDN 網址、驗收，全部自動完成。** 手動上架一件要填十幾個欄位、約 30 分鐘；交給 Claude 大約 3 分鐘，而且欄位不會漏。

- ✅ 適用：開 Shopify 的小店家 / 手作創作者 / 賣獨一件原創商品（畫作、手作、古董）的人，想把上架變快又不出錯。
- 🚫 不建議：上千 SKU 要批量匯入的大型電商（那要走 CSV/ERP 匯入），或還沒開 Shopify 店的人（先開店再回來看）。

## 2. 故事線（第一人稱，符合「解說片＝故事腳本」鐵則）

- **為何有此議題**：在 Shopify 上架一件商品，要填的欄位比你想的多——標題、描述、handle、SEO 標題、SEO 描述、tags、圖片 alt、價格、庫存數、庫存追蹤、超賣政策……十幾個欄位。
- **誰遇到**：我幫家人的原創藝術小店顧線上商店，每一件作品都是獨一無二的原作，只有一件。
- **影響**：手動上架一件約 30 分鐘；更慘的是欄位漏填的代價——我們曾經**全店 32 件商品沒開庫存追蹤**，前台不是顯示缺貨、就是可以被超賣。獨一件的原作要是被買走兩次，就是客訴＋退款。
- **為何別人解不掉**：一般教學只教「照著後台填表」，沒教「結構」；而 Shopify 有些行為反直覺——新建商品**預設不追蹤庫存**、圖片上傳是**非同步**的（傳完當下拿不到網址），自動化最常死在這兩處。
- **我怎麼解**：把商店接上 Claude（官方 Shopify 連接器），上架變成對 Claude 說一句話：**查重 → GEO 結構建商品 → 庫存防呆三件套 → 輪詢等 CDN 圖片網址 → 驗收回報**。
- **我跟別人哪裡不同**：① 0 行程式碼（官方連接器，不用自架 API）② 商品頁照 GEO 結構寫，AI 搜尋引擎會引用 ③ 針對「獨一件」商品的防超賣設定 ④ 每件商品有明確驗收清單，不是「看起來有上就好」。
- **怎麼證明（可量測 before/after）**：before＝手動 30 分/件、32 件庫存全錯；after＝**32 件在線商品全用這條線上架、庫存一次修正 32 件、一句話 3 分鐘上好一件**，之後掛上每天早上的排程，新商品放進資料夾隔天自動上架。
- **CTA**：完整 prompt 放描述欄；訂閱看這個系列怎麼把 FB / IG / Pinterest 也全部自動化。

## 3. 逐章詳細內容（含精確技術事實）

### 【CH1】為什麼「上架一件商品」比你想的累？（Hook · compare）
- 痛點：欄位清單捲不完；漏掉庫存追蹤的真實後果（32 件全中招）。
- 一句結論：**上架不是「填表」，是「結構」。結構交給系統，你只出內容。**

### 【CH2】系統總覽：五站管線（pipeline）
```
① 接上 Claude（Shopify 連接器·一次性）
② 查重（同名商品先查，防重複/$0 草稿）
③ GEO 結構建商品（標題/handle/SEO/tags/alt/描述）
④ 庫存防呆三件套（tracked / DENY / qty=1）
⑤ 圖片 CDN＋驗收（輪詢等 cdn.shopify.com → 檢查清單）
```

### 【CH3】第一步：把 Shopify 店接上 Claude（一次性設定）
- claude.ai → 設定 → 連接器（Connectors）→ 加入 **Shopify** → 登入你的商店授權。
- 授權完，Claude 就有「查商品、建商品、改庫存、跑報表」這些能力，**0 行程式碼**。
- ⚠️ 授權是帳號等級動作，自己點；畫面上店名用示意店。

### 【CH4】第二步：上架前先查重（真實規則 2026-06-24 起）
- 跟 Claude 說先查：同名（中文名或英文名）商品存在 → **沿用，絕不重建**；不存在才建新的。
- 為什麼：重複上架會生出一堆 $0 草稿商品汙染商店（我們踩過，後來清掉 10 筆死資料）。
- 技術對照：`search_products`（query `title:<畫名>`）；中文搜尋不穩時用 tags 過濾全目錄。

### 【CH5】第三步：一句話建商品——GEO 結構逐欄（本片核心價值之一）
| 欄位 | GEO 規則 | 範例（示意商品《山霧晨光》） |
|---|---|---|
| 標題 | 英文關鍵字前置＋中文 | `Original Chinese Ink Landscape Painting \| Misty Dawn 山霧晨光` |
| handle | 英文描述式 | `original-chinese-ink-landscape-misty-dawn` |
| SEO 標題/描述 | 買家搜尋語言＋具體賣點 | 含 hand-painted / one-of-a-kind / 尺寸 |
| tags | 中英三層：品類＋主題＋品牌 | `山水, Landscape, Ink Painting, Wall Art…` |
| 圖片 alt | 描述畫面內容（無障礙＋SEO） | `Hand-painted Chinese ink landscape with misty mountains at dawn` |
| 描述 body | 買家問句式（AI 引擎最愛引用） | 「這幅畫適合掛在哪？」「尺寸多大？」逐題作答 |
- 技術對照：`create-product`（Shopify MCP）＋`shared-product-geo-listing` 逐欄規格。

### 【CH6】第四步：庫存防呆三件套（★全片最重要的坑）
> 真實翻車：2026 年 6 月老闆發現**前台庫存全是 0**。查出全店 32 件 `tracked=false`、`qty=0`，最早 12 件還是 `CONTINUE`（可無限超賣）。根因：**Shopify 新建商品預設不開庫存追蹤**——不是被改掉，是上架當下就沒設。
1. **開追蹤**：`inventoryItem.tracked = true`
2. **防超賣**：`inventoryPolicy = DENY`（賣完就顯示 Sold Out，不能繼續下單）
3. **設庫存**：available `qty = 1`（獨一件原作）
- 技術對照：`productVariantsBulkUpdate`＋`inventorySetQuantities(name:"available", reason:"correction", ignoreCompareQuantity:true)`；一次修正全店 32 件實測可行。

### 【CH7】第五步：圖片傳了怎麼是空的？（非同步陷阱）
- 上傳圖片後 `featuredImageUrl` 常常還是 **null**——Shopify 在背景處理圖片。
- 正解：**輪詢**——每 5 秒查一次，最多 3 次，直到回傳 `cdn.shopify.com` 開頭的正式網址（2026-06-02 實測規則）。
- 加碼：這條 CDN 網址是**公開、無簽名、永久**的圖床——之後發社群貼文（例如 Threads 只吃公開圖床）可以直接沿用，一圖多用。

### 【CH8】驗收清單（別「看起來有上就好」）
1. variant 的 `inventoryQuantity` = 1（⚠️ 別看 `totalInventory`，它是聚合值會延遲，曾見 variant=1 但 total 還是 0）
2. `inventoryPolicy` = DENY
3. 圖片網址是 `cdn.shopify.com` 開頭
4. 前台商品頁開一次：價格、圖、Add to cart 正常
- 技術對照：`get-inventory-levels` 的 `available` 為準。

### 【CH9】成果（可量測 before/after）
- **32 件在線商品**全部用這條線上架。
- 庫存問題**一次修正 32 件**（一句話請 Claude 掃全店補設）。
- 掛上每天早上的排程後：**新商品照片放進資料夾，隔天自動上架**，我不用開後台。
- before/after：手動 30 分/件 vs 一句話 3 分鐘/件。

### 【CH10】補充：安全 / 避坑
1. **改動範圍要圈死**：prompt 裡明講「只動這一件商品」，別讓 AI 批量改到既有商品。
2. **價格必人工確認**：定價是生意決策，讓 Claude 建好後停下來跟你確認價格再上架（我們的管線就是只有定價會停下問人）。
3. **獨一件商品必 qty=1＋DENY**：這是原創/手作賣家的生命線。
4. **連接器授權＝帳號等級權限**：只授權自己的店，用完可隨時在設定裡撤銷。

### 【CH11】片尾禮物：完整 master prompt（見 3.6）

### 【CH12】結尾 Outro（CTA）
- 感謝觀看＋「逐字 prompt 都在描述欄」。
- 訂閱（看 FB/IG/Pinterest 自動化系列）＋按讚＋分享給也在開店的朋友。

## 3.6 完整 Master Prompt（片尾「看到最後的禮物」· 逐字 · 已對照實際管線驗證）

> 片尾 CH11 場景把濃縮版打在畫面上（可暫停複製）；**這份逐字完整版放 YouTube 描述最上方**。
> ✅ 驗證：查重規則、GEO 逐欄、庫存三件套（tracked/DENY/qty=1）、CDN 輪詢（5 秒×3 次）、驗收看 variant 不看 totalInventory——全部對照實際在跑的每日上架管線與 2026-06 實測紀錄。

```
Hi Claude，我開了一家 Shopify 商店，商店已經接上你（Shopify 連接器）。
我現在要上架一件商品，資料如下：商品名稱、幾張照片、價格（我會提供）。
請照下面的流程一次完成，過程中除了「價格確認」都不用停下來問我：

1) 查重：先查商店裡有沒有同名或同一件的商品（中文名和英文名都查）。
   有的話直接沿用既有商品、告訴我連結就好，絕對不要重建，避免產生重複或 0 元草稿。

2) 建商品（照 GEO 結構逐欄填，不可只放中文標題）：
   - 標題：英文關鍵字前置＋中文名（例：Original Chinese Ink Landscape Painting | 山霧晨光）
   - handle：英文描述式（例：original-chinese-ink-landscape-misty-dawn）
   - SEO 標題與 SEO 描述：用買家會搜尋的語言，寫進具體賣點（手繪、獨一件、尺寸）
   - tags：中文品類＋英文品類＋主題關鍵字三層
   - 每張圖片都要有描述畫面內容的 alt 文字
   - 商品描述用「買家會問的問題」當小標、逐題回答（適合掛哪裡？尺寸多大？怎麼保養？）

3) 價格：用我給的價格建好之後，停下來讓我確認一次再繼續。

4) 庫存防呆（這件是獨一無二的原作，只有一件）：
   - 打開庫存追蹤（tracked = true）
   - 超賣政策設「賣完即止」（DENY）
   - 庫存數設 1
   - 注意：Shopify 新建商品預設「不追蹤庫存」，這三項一定要在建完商品後補設。

5) 圖片網址：等 Shopify 回傳 cdn.shopify.com 開頭的正式圖片網址。
   圖片是非同步處理的，如果還拿不到，每 5 秒查一次、最多 3 次。

6) 驗收：最後給我一份清單，逐項列出——
   variant 的庫存數量（要用 variant 的數字，不要用 totalInventory，那個會延遲）、
   超賣政策、正式圖片網址、前台商品網址，讓我逐項核對。

安全要求：整個過程只能動「這一件」商品，不要修改商店裡任何既有商品；
授權用的商店權限只給我自己的店；任何要花錢或改價格的動作都先問我。
```

## 4. 視覺素材清單（哪些用重建、哪些用示意）

| 章節 | 畫面 | 來源方式 | 為何 |
|---|---|---|---|
| CH3 | Claude 連接器設定頁 | ⚠️ 程式重建（黑曜石風），店名用示意店 | 概化示意店原則 |
| CH5 | Shopify 後台商品編輯頁（GEO 欄位逐欄亮起） | ❌ 一律程式重建 | 真後台含店家資料 |
