## 逐句旁白稿（編號＝章-句，要改直接說「7-3 改成…」）

### CH1 一鍵發布 demo（Hook）
- 1-1 我想告訴各位，發一篇小紅書，從影片、標題、正文，到八個標籤、五個章節，全部是 Claude Code 自動完成。
- 1-1b 你只要出創意；就算你講不清楚要做什麼，讓它問你三十個問題，問到它懂為止。
- 1-2 這不是概念展示，是我每天在跑的真實流程。
- 1-3 而且 Claude 動手之前，會先把它打算怎麼做講給我聽，我點頭，它才自動執行。
- 1-4 這支影片，我把這條「我出主意、Claude 出雙手」的發文產線，一站一站拆給你看。

### CH2 全景七站地圖
- 2-1 整條產線，Claude 幫我拆成七站。
- 2-2 前兩站是地基，環境建置、防封框架。
- 2-3 中間三站是內容產線，文案、素材，還有重頭戲，一鍵自動上傳。
- 2-4 最後兩站，發布前的把關，跟發布後的營運。
- 2-5 每一站 Claude 都自動執行，但關鍵決定，它一定先問過我。

### CH3 站一 環境建置
- 3-1 第一站，Claude 得先解決一個大前提，平台看得出你是不是機器人。
- 3-2 一般的自動化工具，一啟動瀏覽器，就帶著機器人指紋，平台的風控系統一查一個準。
- 3-3 所以 Claude 的做法是，開一個專用的真瀏覽器分身。
- 3-4 它用指令自己啟動一顆真的 Chrome，配一個獨立的使用者資料夾，跟我日常的瀏覽器完全分開。
- 3-5 我只掃碼登入一次，之後登入狀態永久存著，Claude 每次自己接上去，不用再掃。
- 3-6 它不是自己另開瀏覽器，而是從外面，接上這顆已經在跑的真 Chrome。
- 3-7 關鍵在一個叫 webdriver 的屬性，框架直接啟動是 true，一看就被抓；Claude 這樣接上去，它保持 false，看起來就是真人在用。

### CH4 站二 防封三鐵則
- 4-1 第二站，防封。這是 Claude 幫我立規矩、也自己遵守的一站。先講一個代價七天的教訓。
- 4-2 今年六月，我的帳號被封了整整七天。
- 4-3 當時用的是另一套工具，自己啟動一顆帶指紋的瀏覽器，又高頻檢查登入，風控直接把我抓出來。
- 4-4 那七天我想清楚一件事，自動化該省的是苦工，不是判斷。
- 4-5 所以重建流程的時候，我要求 Claude 守三條鐵則。
- 4-6 第一，每一篇都先發僅自己可見，等我自己檢查沒問題，才轉公開。
- 4-7 第二，一天最多一到三篇，絕不衝量。
- 4-8 第三，最後那顆發布按鈕，Claude 永遠不碰，留給我按。
- 4-9 這三條守下來，三十多篇，零事故。

### CH5 站三 GEO 文案
- 5-1 第三站，文案。這一段連內容都是 Claude 寫的，但有規矩。
- 5-2 標題二十個字以內，正文一千字以內，寫成問答的形式。
- 5-3 每個段落的標題，是一個真的有人會問的問題，答案裡一定帶具體數字。
- 5-4 但 Claude 寫完不會直接用，它會自己上網，把每一個數字都查證一遍。
- 5-5 舉個真實例子，金澤的巴士一日券，網路上一堆舊文寫六百日圓，它一查，現在是八百。
- 5-6 錯一個數字，這篇的信任就沒了，所以這一步，它一定親自上網查過才算數。
- 5-7 最後它會幫每段補一行，適合誰、不適合誰，讀者跟搜尋引擎都買單。

### CH6 站四A 圖文發布包
- 6-1 第四站，素材。先講圖文筆記。
- 6-2 Claude 把每一篇的素材，自動整理成一個固定格式的資料夾，我叫它發布包。
- 6-3 裡面三樣東西，一張三比四、壓好字的封面，一組編號排好的圖片，一個文案檔。
- 6-4 重點是，上傳腳本只認資料夾格式，不認內容。
- 6-5 所以只要格式對，京都的、金澤的、任何一篇，Claude 都用同一句指令發出去。

### CH7 站四B 實拍 vlog 自動剪
- 7-1 影片筆記更有趣，連剪輯都是 Claude 自動完成的。
- 7-2 金澤清晨的實拍，二十二支我用手機亂拍的片段，Claude 把它剪成一支三分半的成片。
- 7-3 第一步，它自己抽好縮圖，還幫我標出哪幾支有家人入鏡，問我要不要剔除，我一點頭，它就自動刪掉。
- 7-4 第二步，它把同一個地點的鏡頭自動排在一起，順序照文案裡的走法，這樣後面的章節才乾淨。
- 7-5 第三步，它量測每一段的運鏡速度，判斷我手持拍得又快又晃，自動整體放慢兩倍半，晃動感降了將近六成。
- 7-6 第四步，自動配上低音量的背景音樂，頭尾淡入淡出。
- 7-7 第五步是我最喜歡的一招，它把封面海報直接烘進影片的第零秒。
- 7-8 因為平台預設抓第一幀當封面，這樣連「上傳封面」這個步驟，都被它省掉了。
- 7-9 最後，它把每個章節的時間點跟名稱，存成一個小小的清單檔，待會兒上傳有大用。

### CH8 站五 一鍵自動上傳
- 8-1 第五站，重頭戲。上傳這一步，Claude 一句指令，自動做完六件事。
- 8-2 上傳影片、填標題、貼正文、打標籤、設成僅自己可見，最後把章節填好。
- 8-3 這裡有幾個 Claude 踩過坑才學會的關鍵細節。
- 8-4 第一，標籤不是打上去就好，它會等平台的下拉選單跳出來，名字精準命中才選，這樣才是真話題、有流量入口。
- 8-5 第二，章節列表會自己依時間排序，所以它先填名稱、再填時間，順序反了，內容會被打亂掉光。
- 8-6 第三，也是我覺得整條產線最重要的一條，每填一項，Claude 都會把頁面上的值重新讀回來核對。
- 8-7 跟預期一致才存，對不上就自動取消。
- 8-8 寧可不存，也不存錯，這樣的自動化我才敢放心用。
- 8-9 補一個工程細節，影片一百多 MB，一般網頁自動化會撞到五十 MB 上限，Claude 改走瀏覽器的除錯通道，只把檔案路徑交給 Chrome，大小就沒有限制了。

### CH9 坑① 可見範圍自己變
- 9-1 接下來兩個坑，是 Claude 幫我擋下來的，每一個都可能讓前面的努力歸零。
- 9-2 第一個坑，發布頁閒置太久，可見範圍會自己跳回，公開可見。
- 9-3 我親眼看過，設好的僅自己可見，自己變回了公開。
- 9-4 要是沒發現就發布，防封第一鐵則直接破功，草稿內容全公開見人。
- 9-5 所以 Claude 在按發布前的最後一刻，一定會自動重讀一次這個欄位，確認還是僅自己可見。

### CH10 坑② 草稿吃素材
- 10-1 第二個坑更狠。
- 10-2 草稿存回去，再拿出來，影片跟章節會被平台清空，只剩下文字。
- 10-3 標題還在，正文還在，但影片顯示，請上傳視頻，章節整個歸零。
- 10-4 Claude 的解法是一套自動重傳流程，重新上傳影片、等轉碼，再把章節清單重填一次。
- 10-5 還記得剛剛那個章節清單檔嗎，因為章節存成檔案，它重填只要一分鐘。
- 10-6 這就是整條產線的中心思想，設定都存成檔案，頁面上的東西隨時會消失，檔案裡的永遠能重來。

### CH11 站六 人工三步
- 11-1 第六站，誠實講講 Claude 不會自己動手的地方，我試過了，有三件事它一定停下來等我。
- 11-2 第一，原創聲明的開關，程式去點沒反應，平台故意做成只吃真人的手勢。
- 11-3 第二，添加地點，自動選很容易選錯，錯一個地點，整篇的可信度打折。
- 11-4 第三，就是那顆發布按鈕，這是我立的鐵則，不是技術限制。
- 11-5 所以 Claude 把一切填好就停住，我過來檢查一遍，點三下，發布。
- 11-6 這三下，是整條產線唯一的人工，我把它當成最後一道把關。

### CH12 站七 發布後營運
- 12-1 發布之後，還有第七站。
- 12-2 僅自己可見的狀態下，我用讀者的眼睛再看一遍，畫面、數字、標籤都對，才轉公開。
- 12-3 同一個系列的筆記，加進同一個合集，平台會自動幫我把上一篇的合集帶進來。
- 12-4 低頻，但穩定，帳號的權重就是這樣慢慢養起來的。

### CH13 成果＋Outro

- 13-2 以前手動發一篇影片筆記，上傳、填寫、封面、標籤、章節，大概四十分鐘。
- 13-3 現在，我把素材丟進資料夾，一句指令，含上傳跟轉碼，前後三分鐘，其餘全是 Claude 自動完成。

- 13-5 而且這套思路不只小紅書，任何有發布頁的平台，Claude 都能照這七站幫你搭一條產線。

## Prompt 逐字表（tutorial-video-show-claude-prompts；每句都對照 automation-pw 的 xhs-chrome-launch.sh + xhs-post-video.mjs 驗證過）

**開場總 prompt（涵蓋全局）**
> Hi Claude，幫我在自己電腦上做一套「小紅書全自動發文」：用 Playwright 接管我自己開的真 Chrome（不裝自動化指紋、webdriver 保持 false），一句指令就把影片、標題、正文、標籤、可見範圍、章節全部填好，最後停在發布鈕讓我自己按。請一步步帶我做。

**各站 prompt（畫面 💬 方塊逐字）**
- CH3 環境：對 Claude 說——用系統 Chrome 開 debug 埠（--remote-debugging-port=9222）＋獨立 profile，不要加 --enable-automation 讓 navigator.webdriver 維持 false，再用 connectOverCDP 從外面接上。
- CH4 防封：對 Claude 說——加三條防封規矩：先發僅自己可見、一天最多 1–3 篇、發布鈕永遠留我自己按。
- CH5 文案：對 Claude 說——文案標題≤20字、正文≤1000字、寫成問答體，每個數字你自己上網查證過再寫。
- CH6 發布包：對 Claude 說——把每篇素材整成固定格式資料夾：3:4 壓字封面、依序編號的圖片、文案.txt；腳本只認格式。
- CH7 剪輯：對 Claude 說——把這批亂拍片段自動剪：抽縮圖濾家人、按走法分段、太晃放慢 2.5x、配 BGM、封面烘進第 0 秒、存章节.tsv。
- CH8 上傳：對 Claude 說——一句指令自動上傳：CDP setFileInputFiles 傳路徑繞 50MB、等轉碼、填 6 項、標籤精準命中、章節先名後時間讀回核對、停在發布鈕。
- CH11 人工：對 Claude 說——這三件停下讓我手動：原创声明、添加地点、按發布。

**片尾 master prompt（看到最後的禮物 · YouTube 描述最上方也放這段逐字）**
> Hi Claude，我想在自己 Mac 上做一套「小紅書全自動發文」，用 Playwright 接管我自己開的真 Chrome、不靠付費工具。請一步步帶我做，要我去哪點什麼也講清楚：
> ① 環境：用系統 Chrome 開 `--remote-debugging-port=9222` ＋獨立 profile `--user-data-dir=~/.xhs-chrome-profile`，不要加 `--enable-automation`，讓 `navigator.webdriver` 維持 false；我第一次自己掃碼登入創作平台。
> ② 接管：用 `chromium.connectOverCDP('http://localhost:9222')` 接上這顆已登入的真 Chrome，取現有 context 與分頁。
> ③ 發布包：定「一個資料夾＝一篇筆記」格式——`00_封面.jpg`(3:4壓字)、編號圖片、`文案.txt`(標題/正文/標籤)、影片版加 mp4＋`章节.tsv`(每行 `MM:SS<TAB>章節名`)；腳本只認格式。
> ④ 上傳腳本：開 `creator.xiaohongshu.com` 發布頁，用 CDP `DOM.setFileInputFiles` 把影片路徑塞進 `input.upload-input`（繞過瀏覽器 50MB 限制）；輪詢等標題框出現＝轉碼完成(最多180s)；自動填標題、正文(tiptap)、標籤(打 #tag 等下拉、精準命中才 Enter)、設「仅自己可见」、封面設 `00_封面.jpg`、章節(先名後時間、讀回核對一致才存)。
> ⑤ 安全防封：一律先發「仅自己可见」自檢才轉公開；一天≤1–3篇；發布鈕永遠留我自己按；發布前手動開原创声明、添加地点、確認合集；cookie 當密碼不外流。
> ⑥ 給我一句話跑的指令 `node xhs-post-video.mjs "<發布包資料夾>"`，並教我確認真的接上了。
> ⚠️ 小紅書官方並不鼓勵自動化發文，請幫我壓低頻率、內容真實，風險我自負。
